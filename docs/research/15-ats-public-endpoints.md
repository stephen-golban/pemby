## What changes connector design

1. **Recruitee will require a token.** The docs now say: "Deadline for introducing the token to calls is **10 February 2027**. Calls without the authorization header will return the `401 Unauthorized` error". The token (`X-Careers-Sites-Token`) is generated by a user of the employer's account. https://docs.recruitee.com/reference/authentication-1 (page updated 2026-08-12). Keyless reading of Recruitee has about five months left.
2. **SmartRecruiters needs N+1 calls.** The list returns no description, compensation, `postingUrl` or `applyUrl`. Each posting needs `GET /v1/companies/{id}/postings/{postingId}`. A dead company returns 200 with an empty list, so it looks the same as a company with no openings.
3. **The Workable endpoint moved.** The documented `www.workable.com/api/accounts/{sub}` returns a Cloudflare 302 to `apply.workable.com/api/v1/widget/accounts/{sub}`. Call the new host directly.
4. **Personio `?language=en` drops descriptions.** For `1komma5grad`, 34 of 316 positions had descriptions with `?language=en`, and 315 of 316 without it. Leave the parameter out.
5. **Not every vendor gives an updated time.** Lever has none (`createdAt` epoch ms only). Ashby has only `publishedAt`, SmartRecruiters only `releasedDate`, Workable only `published_on` / `created_at`, and Personio only `createdAt`. Change detection must hash the content. Only Greenhouse (`updated_at`) and Recruitee (`updated_at`) expose one.
6. **Greenhouse `pay_transparency=true` also works on the list call.** For `figma` it returned 101 ranges. It is documented only for the single-job call.
7. **Payloads are large.** Lever `palantir`: 316 postings, 6.1 MB, 15.7 s. Greenhouse `stripe` with `content=true`: 648 jobs, 5.0 MB. Ashby `ramp`: 148 jobs, 2.7 MB. Use generous timeouts and streaming JSON where possible.

## Greenhouse (Job Board API)

Doc: https://docs.greenhouse.io/job-board.html

1. **Endpoints.** List: `GET https://boards-api.greenhouse.io/v1/boards/{board_token}/jobs`. One job: `GET .../jobs/{job_id}`. Both return 200 for `stripe` (live).
   - EU: `boards-api.eu.greenhouse.io` does not resolve (NXDOMAIN, live). `job-boards.eu.greenhouse.io` does resolve.
   - The docs do not mention an EU API host. Whether EU-hosted boards are served from `boards-api.greenhouse.io` is **UNVERIFIED**.
2. **Descriptions.** List param: "`content` If set to true, include the full post description, department, and office of each job post."
   - `content` is HTML with entities escaped (`&lt;h2&gt;`). Unescape it before sanitizing (live).
   - Salary: `pay_transparency=true` adds `pay_input_ranges`. It is documented on the single-job call and worked on the list (live).
3. **Pagination.** None on `/jobs`. `meta.total` equals the number of jobs returned (648 of 648 for stripe, live). The docs describe `page` only for the education endpoints.
4. **Fields (live).**
   - Identity and text: `id` (external id), `internal_job_id`, `title`, `content`.
   - Location: `location.name` is one free-text string, e.g. "San Francisco, CA • New York, NY • United States". `offices[]` holds office names and hierarchy.
   - Department: `departments[].name`.
   - Workplace type and employment type: no structured field. Custom `metadata` may hold them (often `null`).
   - Salary: `pay_input_ranges[]` with `min_cents`, `max_cents`, `currency_type`, and `title` such as "Annual Base Salary Range:". There is no structured period.
   - Posting URL: `absolute_url`, often the company's own site (`stripe.com/jobs/search?gh_jid=…`). There is no separate apply URL.
   - Times: `updated_at`, `first_published`. Also `application_deadline`, `language`.
5. **Rate limits.** Not documented on the Job Board page. The only limits Greenhouse documents are for Harvest (https://docs.greenhouse.io/harvest.html), which does not apply here. robots.txt disallows only `/embed/` (live).
6. **Removed job:** 404 `{"status":404,"error":"Job not found"}` on `/jobs/{id}` (live). **Unknown board token:** also 404 with the same body (live). Verify one job with `/jobs/{id}`.
7. **Terms.** "Job Board data is publicly available, so authentication is not required for any GET endpoints." (job-board.html). No statement for or against third-party reading was found.
8. **Example:** `stripe` (648 jobs), `figma` (has pay ranges) (live).

## Lever (Postings API)

Doc: https://github.com/lever/postings-api (README.md, master)

1. **Endpoints.** `GET https://api.lever.co/v0/postings/{site}?mode=json` and `GET .../{site}/{posting-id}`.
   - EU instance: `https://api.eu.lever.co/v0/postings/`. It answers live: `leverdemo` returns 200, and `palantir` returns 404 because that site lives on the global instance. A site exists on one instance only, so try global first, then EU.
2. **Descriptions.** The list includes `description` (HTML), `descriptionPlain`, `opening*`, `descriptionBody*`, `lists[]` (requirements and similar) and `additional*`. No detail call is needed.
3. **Pagination.** "`skip` skip N from the start; `limit` only return at most N results." Neither is required: without them all 316 palantir postings came back (live). No maximum is documented. End = fewer than `limit` returned.
4. **Fields.**
   - Identity and text: `id` (UUID), `text` (title).
   - Location: `categories.location` is the primary; `categories.allLocations[]` has all of them. Also `country` (ISO alpha-2).
   - Workplace: `workplaceType` (`unspecified|on-site|remote|hybrid`).
   - Department and type: `categories.team`, `categories.department`, `categories.commitment` (employment type).
   - Salary: `salaryRange{currency,interval,min,max}`, optional.
   - URLs: `hostedUrl`, `applyUrl`.
   - Time: `createdAt` (epoch ms, live; not in the README). There is **no updated time**. `updatedAt` was absent (live).
5. **Rate limits.** Only the application POST is limited (">2 application POST requests per second" returns 429). No read limit is documented. `api.lever.co/robots.txt`: `Allow: /`, `Crawl-delay: 1` (live).
6. **Removed posting:** 404 `{"ok":false,"error":"Document not found"}` (live). **Unknown site:** same 404 and body (live). This makes "site gone" and "wrong instance" look the same. Verify one posting with `/{site}/{id}`.
7. **Terms.** The README says published postings are publicly viewable and may be read by third parties; all other postings are hidden from the jobs API. The README also says the API "does not … Support cross-origin HTTP requests from sites outside of your company's domains", which matters only for browsers, not server calls.
8. **Example:** `palantir` (global, 316 postings); `leverdemo` (both instances) (live).

## Ashby (public job posting API)

Doc: https://developers.ashbyhq.com/docs/public-job-posting-api (markdown: append `.md`)

1. **Endpoint.** `GET https://api.ashbyhq.com/posting-api/job-board/{JOB_BOARD_NAME}?includeCompensation=true`: 200 for `ramp` (live). No regional host is documented.
2. **Descriptions.** The list includes `descriptionHtml` and `descriptionPlain`. Compensation appears only with `includeCompensation=true`.
3. **Pagination.** None documented; one call returned all 148 jobs (live).
4. **Fields.**
   - Identity and text: `id` (UUID, present live but **not in the doc table**), `title`, `descriptionHtml`, `descriptionPlain`.
   - Location: `location` is the primary string; `address.postalAddress{addressLocality,addressRegion,addressCountry}`; `secondaryLocations[]{location,address}`, e.g. "Remote (Canada)" (live).
   - Workplace: `isRemote`, `workplaceType` (`OnSite|Remote|Hybrid`).
   - Department and type: `department`, `team`, `employmentType` (`FullTime|PartTime|Intern|Contract|Temporary`).
   - Salary: `compensation.compensationTiers[].components[]` where `compensationType == "Salary"`, with `minValue`, `maxValue`, `currencyCode` and `interval` (e.g. "1 YEAR").
   - URLs: `jobUrl`, `applyUrl`.
   - Time: `publishedAt`, "ISO DateTime when the job was last published". There is no updated time.
   - `isListed`: "If false, this listing should only be available via direct link". Drop unlisted jobs.
5. **Rate limits.** Not documented on that page or in https://developers.ashbyhq.com/llms.txt; the only limits there are for `report.*`. Response header `cache-control: public, max-age=60, stale-while-revalidate=60` (Cloudflare) (live), so polling faster than 60 s gains nothing.
6. **Removed job:** it drops out of the list. There is no public single-job endpoint; `jobPosting.info` requires the `jobsRead` API key. **Unknown board:** 404 `Not Found` (live).
7. **Terms.** The doc frames the API as "If you host your own careers page, you can use this data to populate it." For partners, Ashby offers "Dedicated Partner Job Feeds": "Ashby customers can opt-in to sharing their jobs with the partner's service … updated hourly". The partner feed has `updatedAt` and `organizationName`. Contact integrations@ashbyhq.com. https://developers.ashbyhq.com/docs/dedicated-partner-job-feeds. No statement for or against third-party reading of the public API.
8. **Example:** `ramp` (148 jobs) (live).

## Workable (public jobs / widget)

Doc: https://workable.readme.io/reference/jobs-1 (OpenAPI title "public", server `https://www.workable.com/api`, `security: [{}]`)

1. **Endpoints.**
   - Documented: `GET https://www.workable.com/api/accounts/{subdomain}?details=true`. Live, it returns **302** to `https://apply.workable.com/api/v1/widget/accounts/{subdomain}?details=true`, and that returns 200 for `huggingface` (live).
   - Undocumented, both 200 live: `GET apply.workable.com/api/v2/accounts/{sub}/jobs/{shortcode}` (one job) and `POST apply.workable.com/api/v3/accounts/{sub}/jobs` (list, `{results,total}`). They are used by Workable's hosted careers page. **Do not build on them** without a fallback.
   - No regional host found.
2. **Descriptions.** `details` "Includes description field for jobs" (doc). With it the list carries `description` HTML (live).
3. **Pagination.** None on the widget endpoint (6 of 6 jobs, live).
4. **Fields (doc + live).**
   - Identity and text: `shortcode` (external id), `code`, `title`, `description`.
   - Location: `country`, `state`, `city`, plus `locations[]{country,countryCode,city,region,hidden}` (live, undocumented).
   - Workplace: `telecommuting` (bool). `workplace_type` (`on_site|hybrid|remote`) is documented but was **absent live** for huggingface.
   - Department and type: `department`, `employment_type`.
   - Salary: **none**.
   - URLs, with doc labels swapped: the doc says `url` is "URL to the application form" and `application_url` is "URL to the job page". Live, `url` = `apply.workable.com/j/{shortcode}` (job page) and `application_url` = `…/apply`.

5. **Rate limits.** https://workable.readme.io/reference/rate-limits covers token-based API calls only: 10/10 s for account tokens, 50/10 s for OAuth, with `X-Rate-Limit-*` headers and 429. Nothing is stated for the public endpoint, and no rate headers came back (live).
6. **Removed job:** v2 single job returns 404 `Job not found` (live, undocumented). With the documented endpoint only, the job just drops out of the list. **Unknown account:** 404 `Not Found` (live).
7. **Terms.** No statement found in the jobs-1 page or llms.txt. `apply.workable.com/robots.txt`: `Content-Signal: search=yes, ai-input=yes, ai-train=no`, `Disallow:` (empty) (live). The Workable ToS was not read (**UNVERIFIED**).
8. **Example:** `huggingface` (6 jobs) (live).

## SmartRecruiters (Posting API)

Docs: https://developers.smartrecruiters.com/reference/v1listpostings and https://developers.smartrecruiters.com/reference/v1getposting

1. **Endpoints.**
   - List: `GET https://api.smartrecruiters.com/v1/companies/{companyIdentifier}/postings`.
   - Detail: `GET .../postings/{postingId}`, which takes a posting id or uuid.
   - OpenAPI `security: [{}, {key}, {oauth: internal_postings_read}]`: anonymous access is allowed. OAuth is needed only for INTERNAL postings.
   - 200 for `Endava` (live). No regional host.
2. **Descriptions.** Not in the list: list keys are id, name, uuid, location, department, typeOfEmployment, releasedDate, ref and similar (live). The detail call has `jobAd.sections.{companyDescription,jobDescription,qualifications,additionalInformation}.{title,text}` (HTML), plus `postingUrl`, `applyUrl`, `active` and `compensation`.
3. **Pagination.** `limit` ("max value is 100"), `offset`. The response has `offset`, `limit`, `totalFound` (Endava: 190, live). End = `offset + content.length >= totalFound`. Filters include `releasedAfter`, `locationType`, `country`, `language`.
4. **Fields.**
   - Identity and text: `id` (external id; `uuid` also accepted), `name` (title), `refNumber`, description from the detail call.
   - Location: `location{city,region,country,remote,hybrid,fullLocation}`. There is one location only, with no secondary locations.
   - Department and type: `department.label`, `typeOfEmployment.label`.
   - Salary (detail schema): `compensation{min,max,currency,period: HOURLY|DAILY|WEEKLY|MONTHLY|YEARLY}`; null for Endava (live).
   - URLs (detail): `postingUrl`, `applyUrl`.
   - Time: `releasedDate`. No updated time. The doc note: "In order to update content of a job posting … you need to re-post the job", so `releasedDate` moves on re-post.
5. **Rate limits.** https://developers.smartrecruiters.com/docs/rate-limiting: "For most endpoints, SmartAPIs allow up to 10 requests per second" and "up to 8 concurrent requests", counted per credential. The page says `X-RateLimit-*` headers are on every response, but none came back on anonymous calls (live). Timeout advice: "at least **128 s**". Recommended: spread calls, no fixed hour.
6. **Removed posting:** 404 `{"httpCode":404,"code":"RESOURCE_NOT_FOUND",…}` (live). The schema also has `active` (bool). **Unknown company:** 200 `{"offset":0,"limit":100,"totalFound":0,"content":[]}` (live), so a dead company cannot be told apart from one with no openings.
7. **Terms.** https://developers.smartrecruiters.com/docs/authentication: "Some APIs provide access to public data and don't require authentication by design. Examples of such APIs: Posting API". Caution: `api.smartrecruiters.com/robots.txt` allows only `LinkedInBot` on `/v1/companies/` and has `User-agent: * Disallow: /` (live). The docs invite anonymous use while robots.txt excludes other crawlers, so flag this for a policy decision.
8. **Example:** `Endava` (190 postings) (live).

## pg-boss

Source: npm registry and the repo at tag `12.32.0` (https://github.com/timgit/pg-boss/tree/12.32.0, `docs/` = https://pgboss.io).

- **Version.** Latest is `12.32.0`, published 2026-09-14T14:34:05Z (`npm view pg-boss time`).
  - Previous: `12.31.1` (2026-09-13), `12.31.0` (2026-09-10).
  - `engines.node >=22.12.0`. Dependencies: `pg ^8.23.0` (repo pins `pg 8.23.0`), `cron-parser`, `rrule-temporal`, `serialize-error`.
  - The package is ESM (`"type": "module"`), with a named export: `import { PgBoss } from 'pg-boss'`. The README requires Node 22.12+ and "PostgreSQL 13 or higher".
  - Upstream CI runs on a `node:24` container against the unpinned `postgres` image (`.github/workflows/ci.yml`). That image being 18.x today is an inference, not stated.
  - The repo sets no `minimumReleaseAge` (`pnpm config get` returns undefined). pnpm 12's default was not confirmed (**UNVERIFIED**). If an age gate blocks 12.32.0, pin `12.31.1`.
- **Constructor / start.** `new PgBoss(connectionString)` or `new PgBoss({ connectionString, schema, max, application_name, … })`. `boss.on('error', …)` then `await boss.start()`; `start()` installs or migrates the schema unless `migrate: false`.
  - The instance runs supervise, maintenance and cron by default (`supervise`, `schedule` default true).
  - `stop({ graceful: true, timeout: 30000, close: true })` by default.
- **Schema.** Default schema `pgboss`; the role needs `CREATE` (docs/install.md).
  - Tables created: `version`, `queue`, `schedule`, `subscription`, `bam`, `warning`, `job_dependency`, `job` (partitioned parent), `job_common`, per-queue partitions when `partition: true`, and `queue_stats` (src/plans.ts).
  - Uninstall: `DROP SCHEMA pgboss CASCADE`.
  - The Drizzle migrations must not touch this schema.
- **createQueue.** `await boss.createQueue(name, { policy, retryLimit, retryDelay, retryBackoff, retryDelayMax, expireInSeconds, retentionSeconds, deleteAfterSeconds, deadLetter, heartbeatSeconds, partition, notify })`.
  - The queue must exist before `send()` / `schedule()`; otherwise "Queue X does not exist" / "not found" (src/manager.ts, src/timekeeper.ts).
  - `policy`: `standard` (default), `short`, `singleton`, `stately`, `exclusive`, `key_strict_fifo`. Policy and partition cannot be changed with `updateQueue`.
- **send + singleton.** `await boss.send(name, data, { singletonKey, singletonSeconds, singletonNextSlot, startAfter, priority, retry…, expireInSeconds })` returns the id, or `null` when throttled.
  - **On a `standard` queue, `singletonKey` alone does not dedupe.** The only unique index for standard queues is `(name, singleton_on, singleton_key) WHERE singleton_on IS NOT NULL`, so it needs `singletonSeconds` (src/plans.ts `job_i4`). To dedupe per key without a time slot, use a `short` / `singleton` / `stately` / `exclusive` queue. `exclusive` allows 1 queued-or-active job per key, a good fit for "one fetch per board".
  - Helpers: `sendThrottled(name, data, opts, seconds, key)` and `sendDebounced(...)`.
- **schedule (cron).** `await boss.schedule(name, '0 */3 * * *', data, { tz, key, missed, ...sendOptions })` upserts per `(name, key)`. `unschedule(name[, key])`.
  - Schedules are checked every 30 s, at minute resolution; use 5-field cron. RRULE is also accepted. Default tz is UTC.
  - Only one job is sent even with multiple instances.
  - `missed: 'skip'` (default) sends nothing for occurrences missed while down; `'once'` sends one catch-up.
  - At least one instance with `schedule: true` must run.
- **work.** `await boss.work(name, { batchSize = 1, localConcurrency = 1, pollingIntervalSeconds = 2, includeMetadata, perJobResults, transactional, heartbeatRefreshSeconds, groupConcurrency }, async (jobs) => { … })`.
  - The handler **always receives an array**.
  - Returning completes the whole batch; throwing fails the whole batch. With `perJobResults: true`, return `[{ id, status: 'completed'|'failed'|'deadletter', output }]`.
  - Each job has `signal: AbortSignal`. `offWork(name | id)` stops a worker.
- **Retry / backoff.** Queue or job options: `retryLimit` (default 2), `retryDelay` (s, default 0), `retryBackoff` (default false; `retryDelay * 2^retryCount` with jitter), `retryDelayMax`. `deadLetter` receives terminal failures.
- **Expiration.** `expireInSeconds` defaults to 15 min (1..86400); an active job past it is retried or failed. `heartbeatSeconds` (≥10, off by default) detects dead workers sooner.
- **Retention / deletion.** `retentionSeconds` defaults to 14 days, for created/retry jobs not yet run. `deleteAfterSeconds` defaults to 7 days after completion (0 = keep forever). `maintenanceIntervalSeconds` defaults to 1 day. Manual: `deleteJob`, `deleteQueuedJobs`, `deleteStoredJobs`, `deleteAllJobs`.
